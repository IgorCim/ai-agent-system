# ai-agent-system
Автономная агентная система с 30+ инструментами для ML, DevOps, квантовых вычислений и нейроморфных систем
##  Архитектура (3 слоя)
[Мозг] LLM через OpenAI-совместимый API (function calling)
↓ вызовы инструментов
[Руки] hands.py — диспетчер execute_tool() → 30+ инструментов
↓
[Действия] shell / файлы / HuggingFace / Modal / SSH / kaggle / SNN-библиотеки

**Реализация:** Flask-веб-сервер, чат на `localhost:5000`, потоковый вывод через SSE, сессии сохраняются на диск. Собирается в один EXE через PyInstaller + WebView2 как desktop-приложение.

##  «Мозг» — LLM и его механики

- **Модель по умолчанию:** DeepSeek V4 Flash (OpenAI-совместимый API)
- **Ключевые механики:**
  - Стриминг через SSE
  - Function calling в OpenAI-формате
  - Авто-retry при 429/500/502/503/504 с экспоненциальной задержкой
  - Лимит контекста 80 000 символов с автосжатием
  - Защита от «рассужденческого шторма» (ReasoningFlood)
  - До 40 итераций в цикле, таймаут 30 минут
  - **STOP ON SUCCESS** — остановка после успешного результата
  - Маппинг неправильных имён параметров (модель может назвать параметр не так — система сама подменит)

##  Инструментарий (30+)

### Базовые «руки»
- `shell` — выполнение команд Windows/Linux с умной авто-детекцией (6 уровней фолбэк), UTF-8, блокировка браузеров/explorer
- `file_write` / `file_read` — работа с файлами
- `glob` / `grep` — поиск файлов и текста по regex
- `install_python_package` — pip-установка с починкой «битых остатков» (invalid distribution ~)
- `automator` — запуск генератора целых проектов из текстовой инструкции

### Данные
- `fetch_dataset` — скачивание датасетов с HuggingFace в streaming-режиме (без полного скачивания), определение splits/колонок, 5 примеров строк, мета-информация в `<имя>_meta.json`

### ML (4 «прогонщика»)
- `run_local_ml` — локальное обучение (sklearn, pandas, numpy, matplotlib)
- `run_modal_ml` — облачный GPU через Modal.com с self-healing
- `run_ssh_ml` — запуск на удалённом GPU-сервере по SSH (**поддерживает и ключ, и пароль**)
- `parse_ml_metrics` — парсинг метрик в Markdown-отчёт (3 попытки распознавания)

### Квантовые вычисления
- `quantum_simulator` — Qiskit / PennyLane (StatevectorSampler, default.qubit)
- `run_on_real` — отправка на реальное железо IBM Quantum (QiskitRuntimeService + Sampler)
- `run_on_quantum_inspire` — QASM 2.0 на QI (SDK 3.x + REST-фолбэк)
- `transpile_circuit` — транспиляция под топологию (optimization_level=3)
- `apply_error_mitigation` — ZNE (уровни шума 1.0x/1.5x/2.0x → экстраполяция) и DD
- `compare_backends` — таблица сравнения бэкендов + рекомендация

### Био и нейроморф
- `run_bio_ml` — интеграция с Cortical Labs DishBrain (read/frames/stim/plots)
- `run_neuro_ml` — работа с 16 SNN-библиотеками: Lava, Akida, Brian2, snnTorch, Nengo, Rockpool, BindsNET, Sinabs, JAX, PyTorch и др.
- Авто-установка недостающих пакетов в нужное окружение с повтором до 3 раз

##  Кейсы

### Кейс 1: Полная настройка GPU-сервера под ключ
**Задача:** Клиент арендовал VPS с NVIDIA L4 (24 ГБ), но сервер был не настроен — драйверов NVIDIA не было, pip отсутствовал, PyTorch не видел GPU.

**Решение:** Агент через SSH выполнил:
1. Автодиагностику (ОС, CPU, RAM, GPU, пакеты, `/dev/nvidia*`)
2. Установку драйверов NVIDIA (`ubuntu-drivers autoinstall` + догрузка модулей для текущего ядра без перезагрузки)
3. Установку Python-окружения + PyTorch с CUDA 12.1 + TensorFlow GPU
4. Тестовое обучение модели (10 000 примеров × 100 признаков, loss: 1.04 → 0.83 за 0.54 сек)
5. Markdown-отчёт со всеми версиями и командами

**Результат:** Сервер полностью готов к обучению нейросетей за 15 минут, без ручного вмешательства.

### Кейс 2: Архитектурные предложения для Вайб-Маркетолог
**Задача:** Среди 1000+ кандидатов на вакансию AI-разработчика нужно было показать понимание реальных проблем платформы генерации контента.

**Решение:** Предложил 6 архитектурных улучшений:
1. Автоподмена неправильных параметров (маппинг имён)
2. Self-healing при ошибках генерации
3. STOP ON SUCCESS + смета `/generate/estimate` как предохранитель бюджета
4. Автодиагностика перед запуском (`/capabilities` + `/estimate` с `strict=true`)
5. Советник по выбору модели (аналог `compare_backends`)
6. Безопасность API-ключей (никогда не попадают в чат/логи)

**Результат:** Основатель Вайб-Маркетолога лично прочитал работу и отметил:
> *«Адаптивная поправка параметров — ровно то, чего не хватает большинству решений. Повторить упавший шаг умеют все; изменить параметр по причине отказа — почти никто.»*

### Кейс 3: ML-пайплайн от данных до метрик
fetch_dataset (HuggingFace) → run_local_ml / run_ssh_ml (GPU-сервер) → parse_ml_metrics → Markdown-отчёт
При отсутствии данных агент сам вызывает `fetch_dataset`. При `ModuleNotFoundError` — сам ставит пакеты. При `CUDA OOM` — сам уменьшает batch size и повторяет.

##  Системные правила

- **Жёсткий агентный цикл:** план → код → тест → чинить до `Exit: 0`; «частичный успех» = fail
- **STOP ON SUCCESS:** немедленная остановка после успешного результата (исключение — accuracy < 0.5)
- **Self-healing:** авто-установка пакетов, повтор упавшего вызова до 4 раз
- **Безопасность:** ключи никогда не попадают в чат, не пишутся в shell/файл, не логируются
- **Контекст:** лимит 80K символов с автосжатием, 8K на вывод инструментов, сводка задачи при пустом ответе

## ⚠️ Честные ограничения
